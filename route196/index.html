Project Overview

Route 196 is my Capstone Project for Angela Yu's Complete Full-Stack Web Development Bootcamp. It’s a cozy, single-page site inspector designed to streamline basic web research. Simply enter a URL, and the application fetches the site's robots.txt and sitemap.xml, traces its redirect chain hop by hop, and queries the Wayback Machine for historical archives—all accessible via a floating pill menu without needing multiple browser tabs.

The project assignment required integrating a public API using Express and Axios. Driven by a curiosity about website infrastructure and metadata, I decided to build a functional dashboard that gathers these hidden technical details into one unified tool.

As a beginner in backend development, I leveraged Claude (Anthropic's AI assistant) as a learning partner—much like an interactive Stack Overflow. I used it to debug asynchronous code, refine my regex parsing, and handle tricky edge cases like redirect loops and sitemap index files. While the application architecture, feature set, and UI design are my own, working through these concepts ensured I gained a solid, practical understanding of backend HTTP requests and data handling.

Problem & Objective

The main objective of this capstone project was to integrate a public API into a custom Express application using Axios, implement GET endpoints, and establish structured error handling without starter code. To meet the requirements while building something truly functional, I selected the Internet Archive's Wayback Machine API and expanded the application into a comprehensive site inspection utility by building additional URL inspection modules using native fetch. As an early-career developer, this project offered valuable hands-on experience in reading third-party API documentation, handling network edge cases (such as request timeouts, invalid URLs, missing files, and redirect loops), and designing resilient backend logic beyond the standard "happy path."

Technical Implementation

The architecture relies on an Express backend serving four distinct GET endpoints. The robots and sitemap endpoints utilize the native fetch API—wrapped in a custom helper with an AbortController to prevent slow external servers from hanging requests—to parse site metadata, including complex sitemap index files. The wayback endpoint handles the primary Axios integration, executing requests to the Wayback Machine Availability API for the most recent snapshot, alongside secondary calls to the CDX API for capture history. The redirect-check endpoint traces URLs across up to 10 hops, identifying HTTP 3xx responses, meta-refresh tags, and JavaScript window.location redirects using regular expressions, while incorporating loop detection logic. On the client side, EJS renders the core layout, while modular vanilla JavaScript manages single-page tab switching, dynamic fetch calls, asynchronous UI updates, toast notifications, and a light/dark theme toggle backed by LocalStorage.

Implemented Features

Robots.txt Inspector

Fetches and displays any site's robots.txt, showing whether it was found and what it contains, with a clear "not found" state when it's missing.

Sitemap.xml Inspector

Pulls a site's sitemap.xml, parses out every URL (or sitemap-index entry) with regex, and lists them as clickable links.

Redirect Path Tracer

Follows a URL through up to 10 hops, detecting HTTP redirects, meta-refresh tags, and JavaScript redirects, and flags redirect loops instead of hanging forever.

Wayback Machine Lookup

Uses Axios to call the Internet Archive's Availability and CDX APIs, showing the closest archived snapshot plus a short history of recent captures.

Key Outcome & Takeaways

Building this project was a huge milestone in my growth as an entry-level developer, especially when it came to working with third-party data and real-world network reliability. Integrating the Wayback Machine API via Axios challenged me to look beyond ideal scenarios and design robust error handling for request timeouts, unreachable domains, and missing files.

The redirect tracer ended up being the most complex feature to implement. Learning how to catch meta-refresh tags and JavaScript redirects using regular expressions—while implementing loop detection logic to keep the server responsive—required significant testing and iteration. It also taught me the importance of thoroughly reading API documentation to understand response structures rather than making assumptions about the data format.

Using Claude AI as an interactive pair programmer helped me break down complex bugs, evaluate regex patterns, and understand why certain asynchronous requests failed. Instead of relying on quick fixes, this collaborative troubleshooting deepened my grasp of asynchronous JavaScript, Express routing, and network edge cases. Ultimately, this capstone gave me the confidence to explain the technical details and architecture behind every line of backend code.
