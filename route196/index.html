Project Overview

Route 196 is my Capstone Project for Angela Yu's Complete Full-Stack Web Development Bootcamp. It's a "cozy" site inspector — you type in any URL, and it checks that site's robots.txt, its sitemap.xml, traces its redirect chain hop by hop, and looks up its archive history on the Wayback Machine. Everything lives on one page behind a little floating pill menu that switches between the four tools, so you can drop in a URL and immediately see what's going on with it without opening five different tabs.

This capstone's requirement was to pick a public API and build something around it with Express and Axios. I've always been a little curious about the "behind the scenes" stuff websites have, robots.txt, sitemaps, whether a link redirects somewhere weird, whether an old page is still archived anywhere, so instead of picking something unrelated I built the tool I would have actually wanted while poking around other sites.

I want to be upfront that I used Claude (Anthropic's AI assistant) throughout this project — mainly for debugging, reviewing my regex and parsing logic, and talking through edge cases I hadn't thought of, like redirect loops or sitemap index files. I'm still pretty new to backend development, so having something to talk through problems with was a big help, similar to how I'd use documentation or Stack Overflow, just faster and more conversational. The route structure, the four inspector features, and the overall design decisions are mine, and I made sure I understood every part of the code before I called it done.

Problem & Objective

The goal of this capstone was to integrate a public API into an Express app using Axios, with a working GET endpoint and proper error handling, no starter code to build from. I decided to use the Internet Archive's Wayback Machine API for the Axios requirement, and layered on a few more URL-inspection tools using plain fetch so the app would feel like a complete toolkit rather than just one API call wrapped in a page. As someone still early in my dev journey, a big part of this project was learning to actually read documentation for an API I'd never touched before, and figuring out how to handle all the ways a request to a random URL can fail (timeouts, bad URLs, sites with no robots.txt, redirect loops) instead of just assuming the happy path.

Technical Implementation

The backend is an Express server with four GET endpoints. /api/robots and /api/sitemap use the native fetch API (wrapped in a helper with an AbortController so a slow site can't hang the request forever) to pull and parse a site's robots.txt and sitemap.xml, including sitemap index files. /api/wayback is where Axios comes in, it calls the Wayback Machine's Availability API for the closest archived snapshot, then a second call to the CDX API for a short history of recent captures. /api/redirect-check was the trickiest one to build: it follows a URL through up to 10 hops, checking for HTTP 3xx redirects, <meta http-equiv="refresh"> tags, and JavaScript window.location redirects using regex, and stops early if it detects a loop. On the frontend, EJS renders the single page, and vanilla JavaScript handles the floating pill navigation between panels, the four fetch calls to those endpoints, showing loading/result/error states on each output card, toast notifications, and a cozy light/dark ("Latte" / "Mocha") theme toggle saved to LocalStorage.

Implemented Features

Robots.txt Inspector

Fetches and displays any site's robots.txt, showing whether it was found and what it contains, with a clear "not found" state when it's missing.

Sitemap.xml Inspector

Pulls a site's sitemap.xml, parses out every URL (or sitemap-index entry) with regex, and lists them as clickable links.

Redirect Path Tracer

Follows a URL through up to 10 hops, detecting HTTP redirects, meta-refresh tags, and JavaScript redirects, and flags redirect loops instead of hanging forever.

Wayback Machine Lookup

Uses Axios to call the Internet Archive's Availability and CDX APIs, showing the closest archived snapshot plus a short history of recent captures.

Key Outcome & Takeaways

This was my first time integrating a public API with Axios and actually handling all the messy ways a real request can fail, not just the happy path where everything works. I didn't expect the redirect tracer to be the hardest part of the whole project, but figuring out how to detect meta-refresh tags and JavaScript redirects with regex, and catching loops before they hung the server, took a lot of trial and error. I also had to slow down and actually read the Wayback Machine's API docs instead of guessing at the response shape, which was a good reminder that not every API works the way I expect on the first try. Claude was a big help walking through why a regex wasn't matching or why a fetch was timing out, which usually left me actually understanding the fix instead of just pasting one in. I'm still early in my dev journey, but this is the first project where I felt comfortable explaining exactly how every endpoint works, not just that it does.
