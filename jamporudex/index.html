Project Overview

JamporuDEX is my Capstone Project for Angela Yu's Complete Full-Stack Web Development Bootcamp, a personal index of the anime and manga I've watched and read, inspired by Derek Sivers' book notes site (the capstone brief actually points to his site as the model to follow). Instead of books, I track anime and manga: you can search for a title, pull in its cover art straight from MyAnimeList, then save it to your own index with a status, your progress, a rating out of 10, and a short review. Everything is sortable by rating, recency, or title, and filterable by status, and it's all backed by a real PostgreSQL database instead of data that resets every time the server restarts.

I'm a big anime and manga reader, so instead of building another generic to-do list I wanted something themed around what I actually track in my head already. It's the project I'd genuinely want to use myself, which made it a lot easier to stay motivated through the parts that were hard.

I want to be upfront that I used Claude (Anthropic's AI assistant) quite a bit while building this, for debugging errors I got stuck on, reviewing my code for issues I couldn't spot myself, and talking through how to structure trickier pieces like the API fallback logic. I'm still early in my dev journey, so I leaned on it the way I'd lean on Stack Overflow or the docs, just more conversational and a lot faster. That said, the route structure, the database schema, and the decisions about how everything fits together are mine, and I made sure I could explain every part of this project before calling it done.

Problem & Objective

The goal of this capstone was to build a full-stack CRUD app from scratch that persists data in PostgreSQL and talks to a public API, without starter files to lean on. That meant planning my own database schema, figuring out my own Express routes, and deciding how data should flow from the database, through the server, into the EJS templates, and back out again when a user submits a form. As someone still pretty new to backend development, a lot of this project was just sitting with errors until I actually understood why they were happening, instead of copy-pasting a fix and moving on.

Technical Implementation

The backend is an Express.js server connected to a PostgreSQL database through the pg package, with a media_entries table storing each entry's title, MyAnimeList ID, cover URL, status, progress, rating, review, and synopsis. For the API side, I used Axios to call the Jikan API (which wraps MyAnimeList) so users can search for a title and pull in real cover art and synopsis data instead of typing it in by hand. Jikan is a free, community-run API that occasionally times out, so I added a small retry step with backoff before it gives up, and if it's still down after that, the server automatically falls back to the AniList API so search doesn't just break for the user. EJS handles all the server-side rendering, and the frontend uses vanilla JavaScript for the search modal, the edit/delete lightbox, sorting and filtering, and the light/dark theme toggle, no frontend framework, just plain JS.

Implemented Features

Full CRUD with PostgreSQL

Add, view, edit, and delete entries using Express routes and parameterized SQL queries against a real PostgreSQL database, so your index persists between sessions.

Jikan API Search with AniList Fallback

Search MyAnimeList (via the Jikan API) right from the Add Entry modal to pull in cover art and synopsis. If Jikan is down, the server retries automatically and falls back to AniList so search still works.

Sort & Status Filter

Sort your index by rating, recency, or title, and filter by status (Reading, Watching, Completed, On-Hold, Dropped, Plan to Read) using query params on the server.

Dark Theme Toggle

Switch between two dark themes (Tokyo Night Storm and Dracula) with CSS variables and LocalStorage so your preference sticks around as you navigate the app.

Key Outcome & Takeaways

This was my first time connecting a real database to a backend instead of working with in-memory or static data, and it forced me to actually think through my schema before writing any routes instead of figuring it out as I went. Wiring up the Jikan API was its own lesson, I didn't expect a free public API to time out as often as it did, so building in retries and an AniList fallback was something I hadn't planned for at the start, but ended up being one of the parts I'm most proud of. I ran into plenty of bugs along the way, and Claude was a big help talking through why something was failing instead of just handing me a fix, which meant I usually walked away actually understanding the problem. I'm still early in my dev journey, but this is the first project where I felt like I could explain every piece of what I shipped, not just that it worked.
