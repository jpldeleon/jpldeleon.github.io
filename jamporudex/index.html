Project Overview

JamporuDEX is my Capstone Project for Angela Yu's Full-Stack Web Development Bootcamp. Inspired by Derek Sivers' book notes site (a key reference in the capstone brief), I built a personal index for tracking anime and manga. Users can search for titles, auto-fetch cover art from MyAnimeList, and save entries to a custom dashboard with status updates, episode progress, ratings, and short reviews. The app features dynamic sorting and filtering, with full persistence powered by a PostgreSQL database so data survives server restarts.

As an avid anime fan, I wanted to build something tailored to my own interests rather than another standard to-do app. Creating a tool I would personally use kept me engaged throughout the entire development process.

To assist with development, I utilized Claude (Anthropic's AI assistant) to debug errors, review code, and refine complex features like the API fallback logic. Working with AI provided quick guidance similar to consulting documentation or developer forums. While leaning on these tools for technical support, I personally designed the database schema, route architecture, and core application logic, ensuring a complete understanding of the entire codebase.

Problem & Objective

The objective of this capstone project was to design and build a full-stack CRUD application from scratch, utilizing PostgreSQL for persistent data storage and integrating an external public API without starter templates. This required designing a relational database schema, implementing RESTful Express routes, and structuring end-to-end data flow between PostgreSQL, the Express server, and EJS template views. As an entry-level developer, the primary focus was developing a deep understanding of core backend principles, request-response lifecycles, and root-cause debugging.

Technical Implementation

The application is powered by an Express.js backend connected to PostgreSQL via the pg library, utilizing a structured media_entries table to store metadata including MAL IDs, titles, status, progress metrics, ratings, reviews, synopses, and media URLs. External data retrieval uses Axios to interact with the Jikan API (MyAnimeList wrapper) for automated metadata and cover art fetching. To handle API rate limits and potential service degradation, the backend includes exponential backoff retry logic and an automated fallback to the AniList GraphQL API to ensure high availability. The application utilizes EJS for server-side view rendering, alongside vanilla JavaScript on the client side to manage dynamic UI components, search modals, CRUD lightboxes, sorting/filtering operations, and theme toggling without external frontend frameworks.

Implemented Features

Full CRUD with PostgreSQL

Add, view, edit, and delete entries using Express routes and parameterized SQL queries against a real PostgreSQL database, so your index persists between sessions.

Jikan API Search with AniList Fallback

Search MyAnimeList (via the Jikan API) right from the Add Entry modal to pull in cover art and synopsis. If Jikan is down, the server retries automatically and falls back to AniList so search still works.

Sort & Status Filter

Sort your index by rating, recency, or title, and filter by status (Reading, Watching, Completed, On-Hold, Dropped, Plan to Read) using query params on the server.

Dark Theme Toggle

Switch between two dark themes (Tokyo Night Storm and Dracula) with CSS variables and LocalStorage so your preference sticks around as you navigate the app.

Key Outcome & Takeaways

This was my first time connecting a real database to a backend instead of working with in-memory or static data, and it forced me to actually think through my schema before writing any routes instead of figuring it out as I went. Wiring up the Jikan API was its own lesson, I didn't expect a free public API to time out as often as it did, so building in retries and an AniList fallback was something I hadn't planned for at the start, but ended up being one of the parts I'm most proud of. I ran into plenty of bugs along the way, and Claude was a big help talking through why something was failing instead of just handing me a fix, which meant I usually walked away actually understanding the problem. I'm still early in my dev journey, but this is the first project where I felt like I could explain every piece of what I shipped, not just that it worked.
