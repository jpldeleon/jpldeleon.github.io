Project Overview

PixelLog is a blog web app I built as my Capstone Project for Angela Yu's Complete Full-Stack Web Development Bootcamp. It's a nostalgia-themed blog where you can create, view, edit, and delete posts, filter them by category, and sort them by date or title. It's built with Node.js, Express, and EJS on the backend, with no database — posts live in memory and reset when the server restarts, which was one of the project requirements.

Honestly, my love of retro design, pixel aesthetics, and nostalgia is what pushed me to build this in the first place. Instead of another generic to-do list or portfolio clone, I wanted a project that actually felt like mine, something themed around old consoles, childhood games, and the kind of memories I'd want to write about myself.

I'll be upfront about this: I used Claude (Anthropic's AI assistant) while building this, mainly to help me debug issues I got stuck on, review my code for bugs I couldn't see myself, and talk through how to structure a few features. The core logic, routes, and design decisions are mine, but I wanted to be transparent that AI was part of my workflow, the same way I'd use Stack Overflow or documentation, just faster and more conversational.

Problem & Objective

The goal of this capstone was to build a working full-stack CRUD application from scratch, without starter files or a solution to copy from. That meant figuring out my own route structure, deciding how data should flow between the server and the EJS templates, and actually sitting with bugs until I understood why they were happening instead of just pattern-matching a fix. As someone still early in my dev journey, this project was as much about building confidence in reading my own code as it was about shipping a feature.

Key Outcome & Takeaways

This was my first time building something with a real backend instead of just static pages, and it forced me to actually understand how data moves between routes, templates, and the browser instead of just copying patterns. I ran into a few bugs I'm a little embarrassed by now, like a post ID collision that made editing a new post accidentally edit an old one, but working through those (with some help debugging alongside Claude) taught me more than getting it right the first time would have. I'm still early in my dev journey, but this project is the first one where I felt like I actually understood every piece of what I shipped.

Technical Implementation

The backend is an Express.js server that handles routing and form submissions, with EJS as the templating engine for rendering dynamic HTML. Posts are stored in a simple in-memory array on the server rather than a database, per the project spec, which meant thinking carefully about how IDs get assigned so new posts don't collide with existing ones. The frontend uses vanilla JavaScript for interactive pieces like the light/dark theme toggle, category filtering, and sorting, all built without any external UI framework.

Implemented Features

Full CRUD Functionality

Create, view, edit, and delete blog posts using Express routes and EJS forms, all backed by an in-memory data store.

Category Filter & Sort

Client-side filtering by category and sorting by date or title, so posts can be browsed however you like without a page reload.

Light / Dark Theme Toggle

Client-side theme switching with CSS variables and LocalStorage so your preference sticks around as you navigate the app.

Fully Responsive Layout

Custom CSS media queries keep the feed, forms, and toolbar usable across desktop, tablet, and mobile screens.
